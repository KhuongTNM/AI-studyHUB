## Business Rules Needed

- **BR-GC-001 - Group chat is separate from AI Chatbot.** Users create and open study groups from the Group Chat page/sidebar, not from the AI Chatbot toolbar.
- **BR-GC-002 - Group creation limits by package.** Free/base users cannot create groups. Pro users can create up to 20 groups. VIP, Admin, and Sub-admin users can create up to 50 groups.
- **BR-GC-003 - Group join limits by package.** Free/base users can join up to 5 total groups. Pro users can join up to 30 total groups. VIP, Admin, and Sub-admin users can join up to 60 total groups. Created groups count as joined groups.
- **BR-GC-004 - Group chat supports public document sharing.** Only documents with visibility `public` can be shared to a group. Private documents must be disabled/unavailable.
- **BR-GC-005 - Shared private/changed-private files are not downloadable.** If a shared document later becomes private, show it greyed out and block download.

## API Endpoints

All endpoints require `Authorization: Bearer <token>`.

### List My Groups

`GET /api/groups`

Returns groups where the current user is a member.

Response:

```json
[
  {
    "id": "group-id",
    "groupCode": "GRP-ABC-123",
    "name": "SWP391 Team",
    "description": "Assignment discussion",
    "ownerId": "user-id",
    "ownerName": "Hung Nguyen",
    "members": [],
    "messages": [],
    "createdAt": "2026-06-18T13:00:00Z",
    "updatedAt": "2026-06-18T13:00:00Z"
  }
]
```

### Create Group

`POST /api/groups`

Request:

```json
{
  "groupCode": "GRP-ABC-123",
  "name": "SWP391 Team",
  "description": "Assignment discussion",
  "password": "123456"
}
```

Backend must:

- Generate `groupCode` if the client does not send one, and enforce uniqueness either way.
- Hash the group password. Do not store plaintext.
- Check created group count limit.
- Check joined group count limit because created groups count as joined groups.
- Add creator into `group_members` as `owner`.

### Get Group Detail

`GET /api/groups/{groupId}`

Returns one group with members and recent messages.

### Send Group Message

`POST /api/groups/{groupId}/messages`

Request:

```json
{
  "content": "Can someone review this document?"
}
```

Response: created message or refreshed group detail.

### Share Document To Group

`POST /api/groups/{groupId}/documents`

Request:

```json
{
  "documentId": "document-id"
}
```

Backend must reject private documents. For document messages, response should include:

```json
{
  "messageType": "document",
  "documentId": "document-id",
  "documentName": "Lab2.pdf",
  "documentSubject": "Programming",
  "documentVisibility": "public",
  "documentDownloadable": true
}
```

### Download Shared Group Document

`GET /api/groups/{groupId}/documents/{documentId}/download`

Backend must:

- Confirm requester is a group member.
- Confirm document is still public.
- Reject if document is private/deleted.
- Stream the file.

### Add Member

`POST /api/groups/join`

Request:

```json
{
  "groupCode": "GRP-ABC-123",
  "password": "123456"
}
```

Backend must verify password and enforce the user's joined group limit.

### Leave Group

`DELETE /api/groups/{groupId}/members/me`

If the current user is the owner, reject this endpoint and require delete instead.

### Delete Group

`DELETE /api/groups/{groupId}`

Only the owner can delete the group. Deleting should cascade group members and messages.

## Backend Limit Check Suggestion

Resolve limits from the authenticated user and their active subscription:

| Package | Can create | Max created groups | Max joined groups |
| --- | ---: | ---: | ---: |
| Free/base | No | 0 | 5 |
| Pro (`2-4`) | Yes | 20 | 30 |
| VIP (`5+`) | Yes | 50 | 60 |
| Admin/Sub-admin | Yes | 50 | 60 |

Suggested service checks:

```java
int createdCount = groupRepository.countByOwnerId(userId);
int joinedCount = groupMemberRepository.countByUserId(userId);

if (creatingGroup && createdCount >= limits.maxCreated()) {
    throw new BusinessException("GROUP_CREATE_LIMIT_REACHED");
}

if ((creatingGroup || joiningGroup) && joinedCount >= limits.maxJoined()) {
    throw new BusinessException("GROUP_JOIN_LIMIT_REACHED");
}
```

Important: for `POST /api/groups`, run both checks. The owner becomes a group member, so group creation also consumes one joined-group slot.
